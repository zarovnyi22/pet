# Блок 4 — Агент (орієнтир: 2.5 години) — НАЙРИЗИКОВАНІШИЙ БЛОК

Це найбільший ризик по часу в усьому плані. Якщо десь через ~1.5 години в цей блок
(орієнтовно "5:00" від старту дня) tool calling все ще нестабільний — дивись запасний варіант
внизу файлу, не сиди на цьому блоці нескінченно.

## Промпт для Claude Code

```
Прочитай CLAUDE.md, розділ "Агент" — там повний опис циклу, трьох інструментів, лімітів і
системного промпту. Реалізуй:
1. app/agent/tools.py — три інструменти (search_knowledge_base, lookup_product,
   calc_nutrition) з їх JSON-схемами, точно за таблицею з CLAUDE.md
2. app/agent/prompts.py — системний промпт з чотирма правилами з CLAUDE.md
3. app/agent/loop.py — цикл tool calling: максимум 6 ітерацій і 60 секунд, захист від
   зациклення (два однакові виклики поспіль -> примусова фінальна відповідь), валідація
   фінального JSON через Pydantic з одним повтором при помилці, повний trace кожного кроку
4. POST /reformulate — приймає рецептуру + goal (remove_allergen/reduce_sugar/make_vegan) +
   goal_params, повертає substitutions/allergens/nutrition/warnings/trace за схемою з
   CLAUDE.md. Перевищення ліміту ітерацій/часу -> 504 agent_timeout з тим trace, що встигли
   назбирати. Кожен запуск зберігається в reformulation_runs разом із trace і тривалістю.

Прогони приклад з йогуртом з CLAUDE.md на всі три цілі й покажи результат кожного разу.

Коли скажу, що контрольна точка пройдена — закоммить усе з повідомленням "Block 4: agent and
/reformulate" і запуш у `origin main`.
```

## Перевір, перш ніж йти далі

Приклад із розділу "Що будуємо" в CLAUDE.md (йогурт, remove_allergen: milk) — і те саме ще
раз з `reduce_sugar` та `make_vegan`. Для кожного:

- відповідь проходить Pydantic-валідацію (не падає при парсингу)
- кожна заміна в `substitutions` має непорожній `sources` АБО позначку `"confidence": "low"`
  і запис у `warnings`
- нутрієнти до/після в `trace` реально показують виклик `calc_nutrition`, а не просто число
  з повітря
- поле `trace` непорожнє і читабельне — по ньому видно, що саме робила модель

Попроси Claude Code написати тимчасовий тест з навмисно "зациклюваним" сценарієм (та сама
пара tool+аргументи двічі поспіль) і показати, що цикл справді зупиняється примусово, а не
висить.

## Запасний варіант (якщо не встигається)

Якщо вільний tool-calling цикл не стабілізувався — попроси замінити його на фіксований
пайплайн з трьох кроків (код сам у заданому порядку викликає search_knowledge_base →
lookup_product → calc_nutrition, а LLM лише формулює пошуковий запит і фінальний текст
обґрунтування). Це прийнятний свідомий компроміс — головне чесно написати про нього в
README пізніше (Блок 6), а не приховувати.
