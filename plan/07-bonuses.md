# Блок 7 — Бонуси (тільки після завершення основного блоку)

Бонуси не впливають на готовність проєкту, брати тільки якщо основний блок вже пройшов усі
перевірки з `plan/06-packaging.md`. Порядок нижче — за цінністю для співбесіди. Кожен бонус —
окремий коміт, і після перевірки кожного — запуш його в `origin main` (як і в основних
блоках, не переходь до наступного бонусу, поки попередній не запушений).

## Бонус 1 — Kubernetes на kind (~1 година)

```
Прочитай CLAUDE.md. Створи папку k8s/ з п'ятьма маніфестами: Namespace, Secret (з ключами і
DATABASE_URL), Deployment+Service для api з liveness/readiness на /health, StatefulSet+Service
для Postgres з PersistentVolumeClaim. Helm не потрібен. Додай у README команди перевірки:
kind create cluster, kind load docker-image, kubectl apply -k k8s/, kubectl port-forward,
curl на /health.
```
**Перевір:** пройди ці команди руками на своєму kind-кластері, curl на `/health` через
port-forward реально відповідає.

## Бонус 2 — GitHub Actions (~30 хвилин)

```
Створи один workflow на push: підняти Postgres як service container (образ pgvector),
встановити залежності через uv, прогнати ruff і pytest, зібрати Docker-образ без push. Додай
бедж статусу в README.
```
**Перевір:** запуш і подивись, що workflow реально позеленів на GitHub.

## Бонус 3 — Гібридний пошук (~45 хвилин)

```
Додай до векторного пошуку повнотекстовий пошук через tsvector у Postgres і злий результати
з векторним пошуком через Reciprocal Rank Fusion. Це особливо має покращити пошук по назвах
інгредієнтів і кодах спек типу SPEC-014, які векторний пошук знаходить погано.
```
**Перевір:** запит із точним кодом спеки (наприклад "SPEC-014") тепер реально знаходить
відповідний документ, де раніше міг не знаходити.

## Бонус 4 — Оцінка якості RAG (~45 хвилин)

```
Створи eval/questions.jsonl з 10 парами (питання, очікуваний doc_id) і скрипт, який рахує
recall@5 для пошуку по цьому файлу.
```
**Перевір:** скрипт реально запускається і виводить число recall@5, не падає.

## Бонус 5 — Хмара (тільки якщо вже є акаунт без картки)

Якщо є безкоштовний акаунт GCP/Neon/Supabase без картки — задеплой api на Cloud Run, Postgres
на Neon або Supabase (з pgvector). Якщо акаунта немає — пропусти деплой і замість цього
попроси Claude Code дописати в README абзац "як би я деплоїв це в хмару" (образ в registry,
managed Postgres, секрети в secret manager, автоскейлінг з нуля).
